## Prompt 23a — Exporter (backend repo)

```
Read CLAUDE.md, docs/FINDINGS.md and docs/schemas/replay_bundle.schema.json (schema v1.0).

Step 0 — inspect, don't build yet: read the real journals in runs/benchmark_v2/*.jsonl and
report.json. Report to me: the record types present, which schema fields map directly, which
must be derived, and anything in the schema the journals cannot supply (e.g. indexer events,
poller lag). Do not invent values for missing data: optional event types are simply omitted.

Step 1 — implement src/leaklab/replay/ (new package):
- export.py: journal + report.json -> one bundle per (run, scenario, replicate).
  * expected / verdict per read come from the ORACLE (IntentTimeline over the run's mutation
    log), exactly as the scoring uses it. error and not_indexed reads -> verdict "unscored",
    never "denied".
  * t_rel_s relative to the scenario mutation's confirmed_at.
  * summary: copied from report.json; ALSO recompute with oracle.scoring.classify and assert
    equality; fail the export loudly if they differ.
  * Redaction: no tenant ids, object/item ids, UPNs, emails, URLs, or admin data. Personas by
    id + fictional display name only; documents by doc_label. Add a test that scans every
    exported bundle for GUIDs, '@', 'sharepoint.com', 'onmicrosoft' and fails if found.
  * provenance: journal file, report file, exporter version, git commit, exported_at.
- validate every bundle against the JSON Schema (jsonschema lib) before writing.
- CLI: uv run python -m leaklab.replay export --runs runs/benchmark_v2 --out <dir>
  Writes <dir>/<run_id>__<scenario>__r<n>.json plus <dir>/index.json (list of bundles with
  run_id, scenario, replicate, systems, and the summary statuses).
- figures.py: from the SAME bundles, generate the two write-up figures as SVG + PNG with
  matplotlib: (1) three-lane timeline of one chosen bundle (green served / red denied /
  grey unscored ticks, vertical line at t=0 labelled "change confirmed"), log or linear time
  axis selectable; (2) dot plot of first_deny_s for every replicate, per scenario x system,
  log-scale, every replicate as its own dot, DID_NOT_CONVERGE drawn at the cap with a distinct
  marker. Captions include n and the config_label caveats. No hand-typed numbers.
Tests: schema validity, oracle-derived verdicts on a fake journal, redaction scanner, summary
equality assertion catches a planted mismatch, figures build from a fixture.
Then export the real benchmark_v2 runs into ../<frontend-folder>/public/replays/ and
runs/figures/. Tell me which bundle best shows S1-entra (longest Setup 0 lag, Setup B clean).
```

## Prompt 23b — Replay UI (frontend repo: the v0 scaffold)

```
This is a Next.js app generated by v0. Read the whole project first and tell me: framework
version, routing (app/ or pages/), UI library, and EVERY place with mock/placeholder data.

Goal: a 3-lane replay page that renders ONLY data from replay bundles in public/replays/
(schema: copy docs/schemas/replay_bundle.schema.json from the backend repo into
src/lib/replay/schema.json and generate TypeScript types from it). No backend calls.

Hard rules:
- Delete all mock data and hardcoded metrics. Every number, label, timestamp and caveat on
  screen must come from a bundle or index.json. Add a test that fails if any component file
  contains numeric metric literals or the strings "mock", "sample", "lorem", "faker".
- The UI never computes verdicts; it renders outcome/expected/verdict from the bundle.
- error and not_indexed render as grey "no answer", never as red.
- Validate each bundle against the schema at load (ajv); show a clear error panel if invalid.

Page /replay (and /replay/[bundle]):
- Bundle picker from index.json (scenario, replicate, run id).
- Three horizontal lanes in this order: SharePoint (setup0), Azure AI Search (setup_a_basic),
  Revocation layer (setup_b). Each lane shows its label + config_label caveat in small text.
- Per lane: ticks for each read of the FLIPPED pair(s) — green = served, red = denied,
  grey = no answer; a red outline/marker on any tick with verdict "leak". Control-pair reads
  shown as a thin secondary row.
- A vertical line at t=0 ("change confirmed"), mutation summary text from the bundle.
- Per-lane clock: elapsed time since t=0 while that lane is still serving; freezes and turns red
  at the lane's first_deny phase event; shows "did not stop within cap" if DID_NOT_CONVERGE.
- Indexer-run markers on the Azure lane if indexer_run events exist.
- Playback: play/pause, scrub bar, speed 1x / 10x / 60x / 300x. Persistent visible label:
  "Real run, played back at {speed}x" (speed from state, not hardcoded copy).
- Summary strip under the lanes: first_deny_s, leak_exposure_s, status per system, from summary.
- Footer: provenance (run id, generation, exported_at, git commit) and the caveats:
  "One test tenant · n per cell in report · tenant admin out of scope", using bundle data.
- Recording-friendly: a "presentation mode" toggle (hides controls except the speed label,
  larger fonts, 1920x1080 layout), dark and light themes.
Performance: bundles have ~1–3k reads; render lanes with SVG or canvas, 60fps at 300x.
Tests: component test with a fixture bundle (ticks, clocks freeze at first_deny, grey for
errors), schema-invalid bundle shows the error panel.
Run the dev server and tell me the URL of the S1-entra bundle recommended in 23a.
```
