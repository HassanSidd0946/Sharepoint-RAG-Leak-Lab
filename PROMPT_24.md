## 24A — Schema v1.1 (backend repo)

```

v1.1 (keep v1.0 bundles loadable; bump schema_version to "1.1" for new exports):

   baseline, so there was nothing to revoke). Do NOT map it to NOT_APPLICABLE. Export
   S1-spgroup bundles with it.
2. Bundle window: trim events to [baseline_start, max over systems of (time of the last
   served read of a flipped pair, conformance time) + 60 s], capped at poll_cap. Record
   provenance.window_start, window_end, reads_dropped. Summary is still computed on the FULL
   journal (assert equality as before); only the replayed events are trimmed.
3. Indexer runs: status "unfinished_at_journal_end" with t_end null (replaces "unfinished").
4. Phase events: add "last_served" per system (time of the last served read of a flipped
   pair after t=0), so the UI can show leak exposure, not just first denial.
5. caveats: required top-level array of strings, generated by the exporter from run/report
   metadata (tenant count, admin out of scope, config labels, sample size). Remove every
   hardcoded caveat string from the frontend.
6. S6 bundles: a second bundle kind ("kind": "agent_trial") with: scenario (S6a/S6b/S6c/
   positive_control), arm, trial, turns[{t, persona, query, path (cache_hit|memory_hit|
   retrieval), similarity, source_doc_labels, delivered_canaries, expected per canary,
   verdict, guard_decision (allowed|denied|n/a), guard_reason}], validity (VALID|INVALID),
   summary from the S6 report. Same redaction scanner, same provenance.
7. Ranking: for each scenario, rank replicates by distance to the per-system medians across
   all three systems; write "rank" and "representative": true for the closest one into
   index.json.
Tests for each change; re-export everything; schema-validate all bundles.
```
